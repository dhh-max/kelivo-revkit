# SoLab 架构概览

面向开发者的公开架构说明。目标读者：想读懂代码、扩展工具或接入自建服务的开发者。
（内部研发过程材料不随开源包分发，这里只描述代码本身的形状。）

## 一句话

SoLab 是一个 Android 优先的 Flutter 应用：既是多模型 LLM 聊天客户端，也是一套
「对话式 APK 逆向工作台」——选一个 APK，由内置助手驱动分析、定位、修改与签名，
产物落在独立工作目录，不覆盖源文件。

## 两条工具面（同一份实现）

同一套本地工具同时服务两条调用通道：

- **端内助手面**：模型在对话里直接调用工具（`features/home/services/` 注册与分派）。
- **MCP 面**：`core/services/mcp_server/` 把工具面暴露给外部 MCP 客户端，
  便于在电脑侧编排同一批能力。

两条通道共用：工具 schema（单一来源）、失败信封规范（`ok/data/error{code,…}` +
顶层 `nextActions`）、参数校验与恢复策略（`tool_error_policy`）。工具名的差异只在
发布形态，不在实现。

## 关键机制

- **任务台账（runtime）**：一次分析对应一条任务，记录状态机、证据、产物血缘
  （`originPath` 指向设备原件）与工具预算；交付报告由台账生成。
- **工作目录与沙盒**：设备上的普通文件夹是分析目标的落脚点；沙盒（PRoot）提供
  命令行环境，二者通过挂载映射互通（`/workspace` 别名指向工作目录）。
- **APK 工具链**：解包/资源表读取/字符串与 DEX 搜索、方法级补丁、Manifest 修改、
  签名与验签（apksig）、SO 分析与汇编编辑（rizin + LIEF，unidbg 做指令级验证，
  Blutter 负责 Flutter AOT 逆向）。
- **上下文治理**：用量估算与快照、达到阈值即自动原地压缩（旧消息总结为摘要，
  时间线保留原文）、按 token 预算保留最近消息。
- **工作流与子代理**：可视化节点画布（`vyuh_node_flow`）编排 AI/条件/HTTP/延迟等
  步骤；子代理把只读或受限工具面派给分身执行，结果与证据回流主任务。

## 目录速查

| 路径 | 内容 |
| --- | --- |
| `lib/features/chat` · `lib/features/home` | 聊天界面、输入条、消息渲染、控制器 |
| `lib/features/solab_apk` | APK 工作台、分析服务、工作区绑定 |
| `lib/core/services/local_tools` | 本地工具注册、错误策略、参数守卫 |
| `lib/features/runtime` | 任务台账、证据与产物、失败记忆、模型网关 |
| `lib/core/services/mcp_server` | MCP 服务端（端口/令牌/工具面） |
| `lib/features/workflow` | 工作流模型、引擎、画布与生成 |
| `android/app/src/main/kotlin/zhou/solab` | 原生工具通道与引擎（Kotlin） |
| `tool/` | 运行期 harness（追踪、基准、回滚测试） |
| `tools/` | 构建/发布与 Blutter runner 流水线脚本 |
